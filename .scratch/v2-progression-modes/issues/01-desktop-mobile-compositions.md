# 01: Desktop/mobile progression compositions

**What to build:** Produce reviewable compositions for both progression modes within the existing V2 visual identity, so the musician can review configuration, whole-sequence response and results before UI implementation.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] Show common/custom progression editing, per-chord beats, transposition, BPM, notes-per-chord, per-quality pools and mix settings without adding product scope.
- [ ] Show Recognition playback, one answer board with arbitrary fill order, whole replay, missing-answer validation, Don’t know, joint submission and per-note review.
- [ ] Show Guided Singing targets up front, full accompaniment, Done readiness after the initial pass, whole reference and per-position ratings including Unknown/unassessed.
- [ ] Show mode results and Overall contribution, accuracy before timing, clear self-rating provenance and replay scope.
- [ ] Include desktop/mobile, narrow/long progressions, repeated chords, empty/error/interrupted states, keyboard focus and overflow handling.
- [ ] Use synthetic examples explicitly; compositions are not practice records or runtime evidence.
- [ ] Record explicit user composition approval before dependent UI implementation. Do not treat ticket-breakdown approval as visual approval.
